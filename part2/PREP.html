Download the Part 2 starter ZIP ↓

If you already have Part 1, do not replace the project with an empty starter. Your agent can safely add the new materials and preserve your work.

2. Let the agent prepare your private setup.

Open this prompt in the same project. It asks for your sender and permitted buyer countries if those facts are missing. It creates private configuration outside the workshop folder and gives you the exact terminal command.

Keys go in ~/.local/share/agentic-gtm/workshop-private/keys/. The configuration saves file paths, not pasted keys. Folder permissions: 0700. Private file permissions: 0600.

No browser field accepts an API key. A connected account does not approve any sending or spending.

3. Connect your own Google mailbox.

Google uses a downloaded client JSON and browser sign-in, not a Gmail API-key string. Use an account and mailbox your company permits for this pilot.

  1. Open Google Cloud Console ↗. Select or create your own project.
  2. In APIs & Services, enable Gmail API, Google Calendar API and Google Sheets API.
  3. Open Google Auth platform. Complete Branding and Audience for your organization. If using External testing, add your exact sender as a test user.
  4. Open Clients → Create Client → Desktop app. Download the JSON. Keep it private.
  5. Copy the connection prompt below. The agent locates your file and starts the supplied browser sign-in. Choose the exact sender account.
  6. Review Gmail read/modify/send, Calendar read-only and Sheets read-only access. The account check must return your sender and primary calendar.

Workspace blocks this app?

Ask your Workspace administrator to allow your own OAuth app and the requested scopes. Keep drafts and local preparation moving while access is blocked. Do not grant company-wide service-account delegation for this desktop route. An approved existing Google mailbox may be used for its own self-test.

Already using Instantly or Apollo? You can bring contact exports from them. The supplied live send adapter is Gmail; connecting those products does not install an alternative sending adapter.

External testing-mode tokens can expire after seven days for these scopes. Reconnect near class if needed. Google token guidance ↗

4. Save and check your ZeroBounce key.

  1. Sign in to your own ZeroBounce account ↗.
  2. Open API → API Keys, then create or select your key. Official key guide ↗.
  3. Open your own Terminal. Paste the exact code/ folder and saved-Python command your agent gave you in step 2.
  4. Run ../save-api-key.py --provider zerobounce with that saved interpreter. Paste only the key at its hidden terminal prompt, then press Enter.
  5. Run the balance-check prompt below. It reads your actual credits; it does not validate addresses yet.
Plan for the unique addresses still needing validation, including your own test. Eleven fresh addresses need eleven validation credits. Reuse current valid results when supported; the actual count and balance are checked before you approve the paid calls.

Key file: keys/zerobounce.key, outside the project. Never paste it into the class website or agent chat.

5. Bring ten companies and buyer sources.

Keep the two targets from Part 1 when they fit. Add eight others. Your agent can propose the list from your saved buyer segment. Bring existing work emails from your CRM or a current contact export when you have them.

If you need a finder, connect one provider you already use. Sixtyfour, RocketReach, MoltSets or Triguna can help with people and company facts. Exa or Tavily can help find public sources. Actual access, credits and cost still need checking.
