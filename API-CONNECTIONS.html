Google mailbox + calendar Part 2

Send reviewed email from your mailbox. Read replies and calendar meetings.

Open Google
  1. Open Google Cloud Console. Create a project named GTM Workshop.
  2. Select that project. Open APIs & Services > Library. Enable Gmail API, Google Calendar API and Google Sheets API.
  3. Open Google Auth platform > Branding. Click Get Started if shown. Enter GTM Workshop, your support email and contact email. Use Internal if your Workspace organization permits it; otherwise use External.
  4. For External Testing, open Audience > Test users > Add users. Add the same sending mailbox you approved in private setup.
  5. Open Clients > Create Client > Desktop app. Name it GTM Workshop. Click Create and download its JSON.
  6. Tell your local agent the downloaded filename. It moves that file to the private path below and sets permissions to 0600. You do not need to find the hidden folder. Keep the file contents out of chat.
  7. Copy the connection prompt below. Sign in with your approved sender when the browser opens.

Where it goes

~/.local/share/agentic-gtm/workshop-private/google-desktop-client.json

Connect Google from code/

python3 -B gtm.py setup-google --client-file ~/.local/share/agentic-gtm/workshop-private/google-desktop-client.json

Success check: connected_mailbox is your exact sender and outreach_sent is 0. Then your agent must read the primary calendar successfully.

If your company blocks Google consent, ask its Workspace administrator to allow your OAuth app. Continue page and message preparation while access is blocked. External Testing tokens may expire after seven days.

Loop & Tie gifts Part 3, optional

Create a reviewed email gift after its funding and meeting gate pass.

Open Loop
  1. Ask Loop & Tie support to register an API integration for your own account. Request the client ID, client secret and approved redirect URL.
  2. Complete the provider’s OAuth flow to obtain the access token. This package has no Loop & Tie login helper. Ask support or your technical owner to complete that step locally.
  3. Run Save key in your own terminal. Paste only the access token at the hidden prompt, without Bearer.
  4. Ask your agent to read your teams and schedulers, save your owned team ID in the private config and show your actual balance.
  5. For a live gift, follow GIFT-GATE-HELPER.md during Part 3. Review the recipient, collection, price and meeting rule before approving one gift.

python3 -B ../save-api-key.py --provider loop_and_tie

Success check: The native team and scheduler reads match your own account. Gift funding and the meeting gate are separate checks.

API access can require provider support. No access token means prepare a gift preview; do not claim a gift was sent. The adapter does not refresh this token automatically.

Netlify page publishing Part 3, optional

Publish one reviewed HTML file to a fresh site you own.

Open Netlify
  1. Sign in to Netlify. Create a fresh workshop project under your personal account. Do not use your existing company site.
  2. Open Applications > Personal access tokens > New access token. Name it GTM Workshop, choose an expiration and click Generate token. Copy it before leaving.
  3. Run Save key in your own terminal. Paste only the token at the hidden prompt.
  4. Open Project configuration > General > Project details > Project information. Copy Project ID.
  5. Ask your agent to save that ID as settings.netlify_site_id in your current private config. Read the authenticated user and site owner.

Where it goes

~/.local/share/agentic-gtm/workshop-private/keys/netlify.key

Save the key in your own terminal, from code/

python3 -B ../save-api-key.py --provider netlify

Success check: The site owner matches the token’s user. Part 3 publishes only after you review the exact page and site.

The upload replaces the selected site with one index.html. Team sites that do not match the authenticated owner remain blocked. No public page is needed in Part 1.
